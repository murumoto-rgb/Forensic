* **Summary:** One-shot ops script to set the R2 bucket's CORS policy — the missing piece that broke the client-side folder export (#5.110.1). The browser `fetch()`es photos directly from R2 via presigned URLs; R2 rejects cross-origin browser reads (`Origin https://forensic-web.vercel.app is not allowed by Access-Control-Allow-Origin`) unless the bucket carries a CORS policy listing the web app's origin. iOS uploads + the server-side worker are unaffected (URLSession + server-to-server bypass CORS). New `server/scripts/set-r2-cors.ts` uses the S3-compatible `PutBucketCorsCommand` with the server's existing R2 credentials to allow `GET`/`HEAD` from `forensic-web.vercel.app` + `localhost:5173` (override via `ALLOWED_ORIGINS`). Run once: `cd server && tsx --env-file=.env.local scripts/set-r2-cors.ts`. Requires the R2 API token to have bucket-config write scope (Admin Read & Write, or Object Read & Write); on AccessDenied the script prints a dashboard fallback. Idempotent. No app code change, no schema / migration / iOS change. After running, hard-refresh the web app and the client-side export downloads photos successfully.
