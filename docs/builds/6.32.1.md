* **Summary:** **Web floor-plan placement parity with iOS (closes a P1 reviewer finding).** Two related bugs in the web floor-plan flow had drifted from iOS's "feet are canonical, pixels are derived" model: (1) `FloorPlanTab.handlePinDrag` (`web/src/components/workspace/FloorPlanTab.tsx`) wrote only `planPixelX/Y` when the user dragged a pin, leaving `floorPlanID`, `localXFeet`, and `localYFeet` untouched — so a web-placed pin carried no real-world coordinates and any later "move to level" or PDF render couldn't reconstruct its position. iOS's `ProjectStore.setPhotoLocation` always sets all four, deriving `localXFeet = (planPixelX − anchorPixelX) / pixelsPerFoot` (and same for Y) from the active plan's calibration. (2) `PhotosTab.moveToLevel` (`web/src/components/workspace/PhotosTab.tsx`) preserved the source plan's pixel coords on the destination plan when moving a photo between levels — the comment said "set them to null" but the conditional `planPixelX: floorPlanId == null ? null : p.planPixelX` did the opposite when moving to a non-null plan. iOS's `setPhotoFloorPlan` clears pixels first, then re-derives them from the photo's saved `localXFeet/Y` against the new plan's anchors so the pin lands at the same real-world position on the new plan. **Fix:** new shared utility `web/src/lib/planCoords.ts` mirroring iOS's formula exactly — `pixelsToLocalFeet(plan, pxX, pxY)` and `localFeetToPixels(plan, lx, ly)`, both returning `null` when the plan is uncalibrated (`pixelsPerFoot <= 0`) so callers preserve existing values instead of emitting NaN. `handlePinDrag` now sets `floorPlanID` (from the active plan), pixels, AND the derived feet via the utility; existing values stay put when calibration is missing. `moveToLevel` clears pixels, then re-derives them from the photo's saved `localXFeet/Y` against the target plan's calibration; photos without saved feet (web-placed before this fix, or never placed) land "unplaced" on the new plan (`planPixelX/Y = null`), matching the original code's *intent*. **Back-compat:** photos placed on web BEFORE this fix have `localXFeet/Y = null`, so move-to-level on those photos lands them unplaced — same as a brand-new photo, the engineer drops a fresh pin. Photos placed on iOS already had feet coords and now round-trip losslessly through web. The `FloorPlan.anchorLocalXFeet/Y` fields exist on the wire but are unused by either platform's conversion today (iOS treats local coords as a delta from the anchor pixel); kept on the wire for future use, not folded into the formula. **Parity check:** no manifest model touched, no `manifestSchemaVersion` bump, no zod change — all four fields were already on the wire. The new `planCoords.ts` utility typechecked clean in isolation; full web typecheck + production build verified in CI.
