* **Summary:** **AI prompt templates now sync between iOS and web (closes the #5.104.1 follow-on).** Web's `/admin/ai-prompt-templates` editor shipped in #5.104.1, but iOS's template manager (`AIPromptTemplateManagerSheet`) and picker stayed local-only — the team's saved prompts never reached the iPhone and vice versa. iOS now treats `app_config.aiPromptTemplates` like its other config keys: **pull on launch** (new `ProjectStore.applyServerAIPromptTemplates` replaces the local array + disk file) and **push on edit** via the new `ProjectStore.onAIPromptTemplatesChanged` hook (debounced 300 ms, 409 → refetch-and-retry, whole-array last-writer-wins — the tagLibrary pattern). New `AIPromptTemplateLibraryWire` wrapper matches the shared `AIPromptTemplateLibrary` shape (`{templates: [{id, name, prompt}]}`); the iOS element struct already mirrored shared `AIPromptTemplate` field-for-field, so no field mapping was needed. **Race-avoidance design note:** the hook fires from the four user-facing mutators (add/rename/update/delete), deliberately NOT from `persistAIPromptTemplates()` — the fresh-install seed path also persists, and putting the hook there would let a fresh install push bundled defaults over the team's templates before the launch pull lands (a race the tagLibrary flow technically carries; not replicated here). **Seed-on-empty** pushes this device's templates when the server has none (starter pack on a fresh team — gives the web admin page a baseline). The existing in-app picker (AI Notes editor → "Load template…") now surfaces team-wide templates with zero UI change. **Matrix repair:** the "AI prompt templates" row still claimed web was 📋 Phase 4 — stale since #5.104.1; now reflects ✅ on both platforms. No server/web/shared code touched (key + zod shipped in #5.104.1).
