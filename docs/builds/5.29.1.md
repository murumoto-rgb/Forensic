* **Summary:** Fix for Build #5.28.1: the canvas recenter math was panning the plan completely off-screen for bottom-docked previews (and was wrong in many right-dock cases too). Root cause: the canvas was inferring the dock direction by checking which of the canvas's edges overlapped the preview panel's bounding rect — but a bottom-docked panel spans the full viewport width and therefore overlaps the canvas vertically (correct) AND horizontally (also correct, but irrelevant). My "prefer the larger reserve" heuristic then locked onto the wrong axis, set `reserveRight = canvasWidth`, computed `targetScreenX = 0`, and `setStagePos` slammed the plan off the left edge. Fix: the panel writes its dock direction as an explicit `data-preview-dock="right" | "bottom"` data attribute; the canvas reads it directly and computes a reserve on the corresponding single axis. Web-only; no iOS, server, shared, or schema change.
