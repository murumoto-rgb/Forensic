* **Summary:** **Web review Wave 2, PR 3: route-level code splitting.** The bundle warning in `pnpm build` had been on for a while — `vite` itself said "Some chunks are larger than 500 kB"; baseline measured was **1,477 kB / 430 kB gzip** in a single `index-*.js` file. Most of that weight is the project workspace (react-konva canvas, PhotoPreviewPanel at 1,614 lines, markup canvas, exports controls) plus five admin pages most users never visit. Switched the eight non-hot-path routes (`ProjectWorkspacePage`, all five admin pages, `ProjectExportsPage`, `SettingsPage`) to `React.lazy` + a shared `RouteSuspense` wrapper that renders a "Loading…" full-screen while the chunk fetches. `LoginPage` and `ProjectListPage` stay in the main bundle — those are the cold-start hot path; lazy-loading them would just shift the chunk fetch to the first interaction. **Measured result:** main bundle drops to **794 kB / 238 kB gzip** (≈45% smaller, ≈193 kB gzip saved on first load). The workspace becomes its own 626 kB / 182 kB gzip chunk that only loads on the first project open; the five admin pages are 5–12 kB each (1–3 kB gzip) and only fetched on visit. **No behavior change**: route activation is the same, the loading state matches the page-level placeholders already in use, and a returning user's browser caches the per-route chunks across sessions. The `lib/supabase.ts` "mixed dynamic + static import" Vite info-warning is the same one that showed up on the baseline build — it's the existing pattern, not introduced here. **Note:** the workspace chunk still exceeds Vite's 500 kB hint — further splitting (e.g. manual Konva chunk, lazy PhotoPreviewPanel) would help but is a separate sized change. The main-bundle win is the user-perceived first-load saving. Web typecheck + build clean.
