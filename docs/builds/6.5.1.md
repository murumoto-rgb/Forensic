* **Summary:** **Performance PR 2 of the iOS review (Wave 2): photo-filter state consolidation + memoized filtering.** (1) **`PhotoFilterState`.** The photo list's 11 independent `@State` filter vars (tag / recommended-use / bucket / favorites / needs-review / validation / measurements / plan / not-in-bucket / location / date + search text) collapse into one `Equatable` struct with per-field docs, a single `isActive` answer, and one obvious reset point. ~120 references re-prefixed mechanically (`activeTagFilters` → `filters.activeTagFilters`); argument labels and the `SearchableIfPhotos` modifier's own binding were excluded and hand-verified. (2) **Memoized `filteredPhotos`.** With any filter active, the filter chain re-ran on **every body render** — including unrelated state ticks like batch-tag progress — doing per-photo lowercasing and tag-set work (search over a 1,000-photo project = 1,000 string scans per tick). New memo caches **membership + order (photo IDs, never `Photo` values — rows always render fresh data even on a cache hit)** keyed on `(filters, tagConfidenceThreshold, photos.count, store.lastSavedAt)`; any save invalidates. The memo lives in a class box inside `@State` so `body` can update it without tripping "modifying state during view update". The existing no-filter fast path is preserved verbatim (returns `project.photos` untouched). (3) **Tiny behavior fix that fell out:** the "· N shown" header annotation previously ignored the measurements-only and date filters (its hand-maintained 10-term `||` chain had drifted from the 12 actual filters — exactly the bug class consolidation prevents); it now uses `filters.isActive`, so the count appears for those filters too. Known bounded staleness: between batch-tagging checkpoints, in-memory tag mutations don't bump `lastSavedAt`, so filter *membership* (not values) can lag ≤25 photos until the checkpoint save — same render data, fresher than the old behavior's full recompute only in that narrow window, and self-heals at every checkpoint. No DB / shared / server / web change; parity contract unaffected.
