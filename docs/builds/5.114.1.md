* **Summary:** Group the Photos-tab Tag filter popover by primary tag so a project with many distinct secondaries no longer renders a single very long flat checkbox list. **Before**: `tagOptions` was `Set<photo.tags[].label>` sorted alphabetically — a 40-secondary project showed 40 unrelated rows side-by-side ("Cracking", "Crazing", "Delamination", "Efflorescence", ...) with no parent context. **After**: new `buildTagGroups(photos)` walks `photo.tags[]`, treats labels with `parentTag === null` as primaries (wins the role if ANY photo tags it that way), and attributes every other label to the parent it's most-frequently tagged under. Orphan parents (a label that only ever appears as another tag's `parentTag`) become primary headers anyway so the hierarchy stays visible even if no photo tagged the primary directly. The new `MultiSelectChipGrouped` component renders each group as a bold uppercase header (selectable as a primary checkbox in its own right) with its secondaries indented under a left border. Search filters across both levels — a query matching a primary keeps every secondary under it visible (so structure stays intact), a query matching only secondaries shows just those rows under their primary header. Selection state shape (`tagLabels: string[]`) and the underlying AND match logic in `usePhotoFilters` are unchanged — only the popover UI changes; existing filters round-trip with no surprises. Popover panel width bumped 64→72, list max-height 64→72. Bucket and Use popovers stay flat (small option sets, no parents). No iOS / schema / API change.
