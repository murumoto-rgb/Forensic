## Build 5.54.1

* **Date:** 2026-06-06
* **PR:** [#84](https://github.com/murumoto-rgb/Forensic/pull/84)
* **Branch:** claude/backfill-bg-thumbs
* **Merge SHA:** 6f50891
* **Summary:** Move the local thumb-regeneration pass off the main actor so the UI stays responsive during backfill. After #5.53.1, a user with 1000+ missing thumbnails saw the app freeze for several seconds while CG decode → 256px downsample → JPEG encode ran sequentially on MainActor. Fix: build the (imagePath, thumbPath) work list on MainActor (cheap — just reads `store.activeProjects` + per-project helpers), hand the immutable snapshot off to a `Task.detached(priority: .background)`, run the heavy CG work there via a new `nonisolated static func regenerateThumbnail(imagePath:thumbPath:)` on `BinaryBackfillService`. Pure file I/O + Core Graphics + ImageIO — no observable-state access, no actor isolation needed. `ProjectStore.makeThumbnail(from:maxPixelSize:)` visibility broadened from `private static` to `static` so the background helper can reuse it (single source of truth for the 256px downsample). The MainActor returns from `await ...detached.value` and posts the summary toast as before. The earlier `ProjectStore.regenerateThumbnailFromLocalImage(for:in:)` instance method is left in place as a public-ish API surface but no longer used by backfill. iOS-only PR. No server / web / shared / supabase change.
