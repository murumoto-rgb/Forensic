* **Summary:** Foundation for app-wide config sync. New `app_config` Supabase table (migration 0004) — generic `key text PK, value jsonb, revision, updated_at, updated_by` rows, same optimistic-concurrency shape as `projects`. Defense-in-depth RLS lets any signed-in user SELECT (team-wide config is intentional); all writes go through the server's secret key. Shared types added in `packages/shared/src/appConfig.ts` mirroring the iOS Swift structs: `TagLibrary`, `InvestigationContext`, `PrimaryTagEntry`, `SecondaryTagEntry`, `AIRulesTemplate`. Per-key zod schemas + an `AppConfigValueSchemaByKey` dispatch map in `validation.ts` so the server's PUT route validates payloads against the right shape. New API shapes in `api.ts`: `GetAppConfigResponse`, `GetAppConfigBundleResponse`, `PutAppConfigRequest`, `PutAppConfigResponse`. New server route `server/src/routes/appConfig.ts` with `GET /v1/config` (bulk fetch every known key), `GET /v1/config/:key` (single key, 404 when not yet set), and `PUT /v1/config/:key` (per-key zod validation + revision check; 409 on mismatch). Parity contract test learns to scope app-config schemas out of the manifest-struct comparison via a tracked `APP_CONFIG_STRUCTS` exclusion — this exclusion shrinks when iOS sync ships in #5.36.1, which will add app-config models to the fixture regen list. No iOS or web client wiring yet: this PR is the data model + endpoints only, so neither platform has anything to read or write until the follow-ups. Web "Re-tag with AI" button needs this in place; that ships in #5.37.1 once iOS push lands. No `manifestSchemaVersion` bump (manifest models unchanged).
