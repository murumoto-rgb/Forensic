* **Summary:** Sprint E2 of the AI-tagging completion plan — server-side prompt compilation. `POST /v1/ai/tag-photo` now accepts an optional pair `{systemPrompt, userText}`: when both are present the server uses them verbatim (existing client-driven behaviour, no breaking change), when both are absent the server compiles the prompt itself from the project's manifest + the team's `tagLibrary` + `aiRulesTemplate` in `app_config`. Half-and-half (one present, one absent) returns 400 with a clear "either both or neither" message — almost certainly a client bug rather than a deliberate request shape. Server-side compilation uses the same shared `compilePrompt(...)` + `compileUserPrompt(...)` the clients use (port from #5.37.1 / #5.38.1 protected by the snapshot parity test), so server-side output is byte-equivalent to what the client would have sent. `PromptCompileError` from compilePrompt surfaces as 422 `no_tag_selection`; missing tagLibrary surfaces as 422 `config_missing` with a hint pointing at the iOS / web admin paths. Shared `AITagPhotoRequest.systemPrompt` + `.userText` become `?: string`; doc comments explain the two modes. The route's project lookup now pulls `manifest` jsonb (was `id` only) so the server has access to `project.photos[*].imageFilename` for the user-prompt photo_id echo. Server-only PR; no migration; web + iOS unchanged (they still send the prompt). Lays the groundwork for future thin clients (CLI tooling, admin one-offs) that don't want to carry the compilation logic. Audit row from #5.45.1 gets an extra `serverDrivenMode: bool` in its `detail` jsonb so cost-tracking dashboards can split the two paths. (Stacked on #75 for the audit_log integration; merge order is #75 → #76.)
