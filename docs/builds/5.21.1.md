* **Summary:** Two changes.
  **(1) Fix every thumbnail showing "Uploading…" on the photo grid.** The Build #5.19.1 batch endpoint returns a `{photoId: url}` map. `files.photo_id` is a Postgres `uuid` column, which returns values in lowercase canonical form, so the server keyed the map with lowercase IDs (`a5f6e276-…`). But iOS manifests store photo IDs in uppercase (Swift `UUID`), so the web sends uppercase IDs and looks the map up with `urls[photo.id]` — a case-sensitive JS object lookup that missed every entry, collapsing the whole grid to the "pending upload" placeholder. The DB match itself was always fine (uuid comparison is case-insensitive); only the response key was wrong. Fix: server now keys the response map by the exact id string the client requested (preserving case), resolving DB rows back via a lowercased lookup table.
  **(2) Expose the deployed git SHA on `/healthz`.** Adds `gitSha` / `gitShaShort` (from Render's `RENDER_GIT_COMMIT`) to the healthcheck response so anyone can confirm which build is live with one unauthenticated GET — Render posts no deploy status to GitHub, so this is the only self-serve "is the new server live yet?" signal.
  Server + shared (response-type field only — no manifest model, no fixture regen, no `manifestSchemaVersion` bump). No iOS change.
