* **Summary:** Non-PencilKit markup canvas on web — closes the deferred follow-on. New `PhotoMarkupCanvas.tsx` opens as a full-viewport modal with the photo on a Konva stage and a transparent drawing layer on top. Tools: **pen** (six preset colors + four widths), **eraser** (Konva `destination-out` composite), **undo / redo** (single stroke stack with redo restoration), **clear** (drops every stroke; one undo restores them — Clear pushes the prior stack onto the redo log). On Save: the drawing-only layer is rasterized to a transparent PNG at the photo's natural resolution via Konva's `toDataURL({ pixelRatio })` math; the PNG is uploaded as `kind=markup_png` through the PR #7 upload pipeline (`uploadFile`); `Photo.markupOverlayFilename` is set to `<photoId>.png` matching iOS convention. iOS reads the same field and renders the PNG on top of the photo — round-trip compatible. New "Markup" section in `PhotoPreviewPanel.tsx` shows "Add markup…" / "Edit markup…" depending on whether an overlay exists, plus an "Overlay saved" pill. The PencilKit-specific stroke data side (`Photo.markupDrawingFilename`) remains iOS-only and is now documented under Platform exclusions. Background image loaded with `crossOrigin: "anonymous"` so the Konva canvas isn't tainted (required for `toDataURL`). Stage sizes itself to its container while preserving photo aspect; on window resize the stage re-measures. No schema change, no shared API change, no iOS change. No `manifestSchemaVersion` bump.
