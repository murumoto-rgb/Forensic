* **Summary:** **PDF pin-size parity (second-review PR B).** The second-pass audit caught a cross-platform inconsistency: iOS's PDF exporter scales floor-plan pins/distress with the user's bubble-size setting (hoisted per-export in #6.4.1), while the web/server exporter hardcoded `r="14"` photo pins, `r="12"` distress circles, and `stroke-width="6"` crack strokes — so the **same project printed differently-sized pins depending on which device exported it**. Now: (1) **Shared** — `PdfExportOptions.pinScale: number` (default 1; documented as mirroring the on-screen `planBubbleScale`). (2) **Server** — `DEFAULT_PDF_EXPORT_OPTIONS.pinScale = 1` + `clampPinScale` (0.5–4, the same range as the `UserPrefs.planBubbleScale` zod bound) in `applyOptionDefaults`; `htmlReport.ts` threads `pinScale` through `planPages → planSection → PlanSectionOptions` and applies it to the photo-pin radius/stroke/font/dy and the distress circle radius + crack stroke width. Legacy jobs and old clients that omit the field render at exactly 1× — byte-identical output to before. (3) **Web** — `ExportPdfControl.start()` injects `pinScale: userPrefs.bubbleScale` (the #6.13.1 cross-device-synced preference) into the create request, so the exported PDF's pins match what the user dialed in on the plan tab — no new modal UI, it simply mirrors the on-screen state, the same mental model iOS users already have. **Matrix:** pin-size row updated to note the closed PDF gap. The two-phase countPages/render discipline is unaffected (pin scale changes glyph geometry inside fixed plan pages; page counts don't depend on it). Typecheck clean across shared + server + web; 68/68 shared tests pass (`PdfExportOptions` is a wire type in the parity ignore set — iOS has its own native exporter options).
