* **Summary:** Sort the project list alphabetically by name on iOS and web. **Before**: iOS sorted by `createdAt` descending (newest first), web rendered whatever the server returned (`updated_at` descending), so the same user saw two different orderings depending on which client they opened. **After**: both platforms sort case- and diacritic-insensitively by `Project.name`. iOS adds a `ProjectStore.projectNameAscending` static comparator using `localizedCaseInsensitiveCompare`, applied at `loadProjects` (initial decode), `commitInMemory` (in-place updates), `delete(_:)` (trash insertion), and `restore(_:)` (untrash insertion); `renameProject` re-sorts automatically because it routes through `save → commitInMemory`. Web wraps the two `api.listProjects()` responses in a `sortByName()` helper that uses `localeCompare(b.name, undefined, { sensitivity: "base" })` for the equivalent case-insensitive behaviour. Server is untouched — its API still returns `updated_at` descending, but both clients re-sort on receive. No schema / API / iOS struct change.
