* **Summary:** Path C #3/8 — replace the per-photo full-page layout (from #5.63.1) and the rigid 1/2/4-up grid (from #5.64.1) with iOS's primary photo-page format: the **contact sheet**. New primitives in `server/src/exports/htmlReport.ts`: `gridDimensions(perPage)` computes a sensible cols × rows for any `perPage` in the iOS-supported 1–12 range (1=1×1, 2/3=1×N stack, 4=2×2, 5/6=2×3, 7/8/9=3×3, 10/11/12=3×4); `annotationsHtml(photo, annotations)` renders a per-cell annotations row driven by the iOS-parity `PdfAnnotationOptions` flags (caption, observation, tags, measurement, reviewerFlag) — each line appears only when its flag is on AND the photo has a non-empty value for that field; `contactSheetTile(photo, blob, planLabel, annotations)` is a single grid cell (header → image → annotations); `contactSheetPage(photos, …)` arranges up to `perPage` tiles on one printed page with inline `grid-template-{columns,rows}` from `gridDimensions`. Old `photoPage` deleted; renderer now chunks `selectedPhotos` by `perPage` and emits one `contactSheetPage` per chunk. `perPage` defaults to 6 (iOS default) — matches `DEFAULT_PDF_EXPORT_OPTIONS.perPage`; existing #5.64.1 jobs with `photosPerPage: 1|2|4` still work via the `options.perPage ?? options.photosPerPage ?? 6` fallback chain. CSS rewrites the photo-page styles: drops `.photogrid-*`, `.photo .*`, `.photo .aifields`, etc.; adds `.contact-sheet`, `.tile`, `.tile-{header,image}`, `.annotations`, `.ann-line`. `page-break-inside: avoid` on each `.tile` ensures Chromium doesn't split a cell across pages. Annotations render in iOS order (caption → observation → tags → measurement → flag). Cover page and plan pages unchanged this PR (plan-mode work lands in #5.69.1). Server only — no schema change, no shared change (consumes the types added in #5.67.1), no iOS change, no web UI change yet. No `manifestSchemaVersion` bump.
