## Build 6.1.1

* **Date:** 2026-06-10
* **PR:** [#170](https://github.com/murumoto-rgb/Forensic/pull/170)
* **Branch:** claude/review-code-visibility-izhPs
* **Merge SHA:** 135d41e
* **Summary:** **Ships the iOS half of project freeze (closes the #5.126.1 gap).** Build #5.126.1 added `Project.isFrozen` (schema v3) with full web UI + server enforcement, but iOS only received the Codable field — no banner, no gating, no toggle, so a project "finalized" on web remained fully editable from the iPhone. This build closes that. **Store chokepoint:** `ProjectStore.save(_:)` now rejects any write where both the stored project and the incoming value are frozen — one guard catches every edit path (photo row actions, plan-viewer drags, distress strokes, trash restore, batch-tag checkpoints) with a "Project is locked" toast; the unlock flip (`isFrozen == false` onto a frozen project) passes through, otherwise unlocking would be impossible. Server pulls bypass the guard via `applyServerProject`, so sync adoption of frozen manifests still lands. New `ProjectStore.setFrozen(_:frozen:)` helper. **UI:** an orange "Locked / finalized" banner section renders at the top of every workspace tab; the camera/distress FABs disappear; the import section and the whole AI tab content hide; the photos header drops Select + renumber; plan rows keep tap-to-view but lose their editor menu and the Add Floor Plan button; bucket management hides (counts stay); the address row becomes read-only. **Export stays available** — that's the point of a finalized project. **New "Project Lock" section on the More tab:** "Lock Project (Finalize)" with confirm dialog / "Unlock Project" direct toggle, mirroring web's Info-tab control; the server still enforces owner/admin on the flip at sync time. **Parity matrix repaired:** header now reads `manifestSchemaVersion: 3` (it still claimed 2 — #5.126.1 bumped code + fixtures but missed the matrix), and the previously missing "Lock / finalize project" feature row is added showing ✅ on both platforms. No schema change (field shipped in v3); no DB / shared / server / web code touched; parity contract unaffected.
