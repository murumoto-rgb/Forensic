* **Summary:** "Restore to bundled default" available on both iOS and web for tag library + AI rules template. Source of truth stays in iOS Swift code (`AIRulesTemplate.defaultText`, `TagLibrary.defaultSeeds`); shipping a new default requires a code change + TestFlight build, satisfying the "only editable via code" constraint. Two new read-only `app_config` keys — `tagLibraryDefault` + `aiRulesTemplateDefault` — carry the iOS-bundled values. `AppConfigSyncer.pullAllFromServer()` pushes them at every launch via new `pushTagLibraryDefault(...)` / `pushAIRulesTemplateDefault(...)` + their refetch-and-retry siblings, idempotent against the existing app_config upsert path (a TestFlight ship with a new bundled default propagates to web on the first launch of the new build). Shared types extended: `AppConfigKey` gains the two new keys, `AppConfigValueByKey` maps both to `TagLibrary` / `AIRulesTemplate`, `AppConfigValueSchemaByKey` reuses the existing zod schemas. Documentation in `appConfig.ts` calls out the editable-vs-default semantics so future maintainers don't add a "save default" UI by accident. Web `api.ts` gains `getTagLibraryDefaultConfig()` / `getAIRulesTemplateDefaultConfig()` (null on 404 — "iOS hasn't connected since this build shipped"). Both admin pages (`/admin/tag-library`, `/admin/ai-rules`) gain a new amber **"Restore default"** button left of Discard / Save: confirms with the user, fetches the bundled-default snapshot, sets the draft to that value (NOT a persist — user still has to click Save to overwrite the editable key). 404 surfaces as a friendly "open iOS once" hint. Stacked on #77 for the seed-on-empty pull-loop change. Merge order: #77 → #78.
