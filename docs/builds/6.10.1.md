* **Summary:** **Fixes the Xcode build failure on main** ("Call to main actor-isolated instance method 'post(_:kind:actionTitle:action:)' in a synchronous nonisolated context" at `ProjectStore.swift:1307`). Root cause: Build #6.1.1's freeze guard in `ProjectStore.save(_:)` posts a "Project is locked" toast, and `ToastCenter` is `@MainActor` — but `ProjectStore` (unlike its siblings `PhotoSyncer` / `AppConfigSyncer`) is **not** a `@MainActor` class, so `save(_:)` is nonisolated and the synchronous cross-actor call doesn't compile. The self-review missed it by assuming ProjectStore shared its siblings' isolation. Fix: wrap the post in `Task { @MainActor in … }` — the exact pattern the file already uses for the iCloud-conflict toast in `checkForUnresolvedConflicts` (the other nonisolated-context toast). The rejection itself stays synchronous (`return current` unchanged); only the banner hops actors, landing a beat later, which is how every other ProjectStore toast already behaves. **Full re-audit of the error class across all nine review PRs (#170–#178) with the corrected isolation facts:** the pre-existing `batchAITag` toast is fine (that method is explicitly `@MainActor`); all PhotoSyncer / AppConfigSyncer toasts are inside `@MainActor` classes; `applyServerReportBranding` / `applyServerAIPromptTemplates` / `setFrozen` make no isolated calls; the new config-sync hooks follow the identical shape the tagLibrary hooks have shipped with since #5.36.1; `CachedThumbnail`'s detached closure touches only nonisolated API (and #6.6.1's `sha256Hex` was already made `nonisolated` for the same reason). This was the single instance. One-line behavioral note: none — same toast, same rejection, same return value. No DB / shared / server / web change.
