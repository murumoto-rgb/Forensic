* **Summary:** Server-side PDF export — PR #1 of 3 for plan item #3. End-to-end pipeline skeleton: enqueue → background Puppeteer render → R2 upload → web download. The PDF in this PR is intentionally a single cover page (project name, photo count, plan count, generation timestamp); PR #2 brings the real per-photo + per-plan report, PR #3 adds the options sheet. New migration `0007_pdf_export_jobs.sql` with one row per export request: `id` UUID PK, `project_id`, `requested_by`, `status` (queued|running|done|failed), `pdf_object_key`, `error_message`, timestamps. RLS lets a user SELECT their own rows; the server's secret key handles all writes. New shared types: `PdfExportJob`, `PdfExportStatus`, `CreatePdfExportRequest` (reserved empty for the options sheet), `CreatePdfExportResponse`, `GetPdfExportResponse`. New server endpoints in `server/src/routes/exports.ts`: `POST /v1/projects/:id/export/pdf` (404 when caller doesn't own the project; 200 with the new job row) and `GET /v1/exports/:jobId` (404 for non-owners; 200 with the job + a 5-min presigned R2 download URL when status is done). New PDF worker in `server/src/exports/pdfWorker.ts` started from `index.ts` after the HTTP listener binds: every 5s it scans for the oldest queued row, atomically claims it via a conditional `update where status='queued'`, renders the minimal cover-page HTML, prints it to a PDF via Puppeteer (headless Chromium reused across jobs to avoid the 250 MB cold-start cost per render, `--no-sandbox --disable-setuid-sandbox --disable-dev-shm-usage --single-process --no-zygote` for Render's container), uploads the buffer to R2 at `exports/pdf/<jobId>.pdf` via a new `putObjectBytes` helper on `r2.ts`, and flips status→done. Render failures land status='failed' with the error surfaced into `error_message`. New `puppeteer` ^24+ dep on the server (~150 MB Chromium download on install). Render config: `PUPPETEER_CACHE_DIR=/opt/render/.cache/puppeteer` added to `render.yaml` so the Chromium binary survives deploys; new `server/.puppeteerrc.cjs` echoes the same cache path. New web component `ExportPdfControl` on `ProjectDetailPage` next to BatchRetagControl — gated on holding the lock; clicking it POSTs the job, polls every 2s, and auto-triggers a hidden `<a>` click on the presigned URL when done so the PDF downloads without a second user click. Five-state UI: queued/running/done/failed/error with reset. **Operator step before merge:** run `0007_pdf_export_jobs.sql` in Supabase SQL editor. **RAM caveat:** Render's free 512 MB tier is tight for Puppeteer; the worker reuses one browser across jobs to stay inside the budget, but Starter tier upgrade (~$7/mo) is recommended if OOMs land. No iOS / shared schema change beyond the API types. No `manifestSchemaVersion` bump.
