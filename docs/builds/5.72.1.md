* **Summary:** Path C #7/8 — chunked rendering retires the 1000-photo cap entirely. The renderer no longer produces one monolithic HTML document; it produces an array of HTML "chunks," each a complete `<!doctype html>` document. The worker pipes each chunk through its own Puppeteer `setContent` → `page.pdf` cycle, then merges the per-chunk PDF buffers with `pdf-lib` into the final document we upload to R2. Memory math: Chromium's working set tracks the per-chunk size (~5 MB HTML, ~30-50 MB DOM at `PAGES_PER_CHUNK = 25`), not the whole report — comfortably inside Render free-tier's 512 MB budget for any project size. Per-chunk RSS logging from #5.65.1 stays; new aggregate "merged" log line surfaces total page count and final PDF size for cost / performance tracking. New `pdf-lib` ^1.17.1 npm dep on the server (~3 MB; pure JS; well-maintained). New `wrapHtml(bodyHtml, styles, project)` + `sharedStyles(options)` helpers in `htmlReport.ts` factor the document scaffold + giant `<style>` block out of the old monolithic template so each chunk gets a consistent shell without duplicating string literals. Contact-sheet renderers (`renderUngroupedContactSheets`, `renderBucketedContactSheets`) now return `string[]` (one element per page) instead of joined HTML; ditto for `renderPlanPages`. New top-level `renderReportChunks(project, projectId, log, options): Promise<string[]>` replaces `renderReportHtml`: builds cover chunk + plan chunk + metadata chunk + N contact-sheet sub-chunks of `PAGES_PER_CHUNK` pages each, ordered per `options.sectionOrder`. Empty sections are dropped before chunking so an over-filtered export doesn't produce orphan chunks. `MAX_PHOTOS_PER_PDF` removed; replaced with `PAGES_PER_CHUNK = 25` as the per-chunk page count. Worker (`pdfWorker.ts`) loops chunks → `setContent` → `page.pdf` → push Buffer; then `PDFDocument.create()` + `copyPages` merge. Empty-selection guard throws clean error rather than producing an empty PDF. Performance: single-chunk Letter PDFs render in ~3-5 s as before; 1000-photo project renders in ~30-60 s (5-7 chunks × ~5-8 s each + merge in <1 s). Server only — no schema change, no shared change, no iOS change, no web UI change. No `manifestSchemaVersion` bump.
