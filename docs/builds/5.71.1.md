* **Summary:** Path C #6/8 — `groupByBucket` + `sectionOrder` honored, the last big iOS-parity behaviour gap on the layout side. (a) `sectionOrder` (`['plan', 'contactSheets', 'metadataTable']` iOS default) now drives the body composition: previously the renderer hard-coded `cover → photos → plans → metadataTable`; now it iterates `options.sectionOrder` and concatenates each section's HTML in that order, filtering out empty entries so a project with no plans / no photos / metadata table off doesn't produce orphan blank pages. The cover page is intentionally NOT in `sectionOrder` (always page 1 when included — same convention iOS uses). iOS default behaviour change: PDFs now default to **plans first, then contact sheets, then metadata table** — matches iOS exactly, was photos-first on the web before this PR. (b) `groupByBucket`: when set, photos are partitioned by `Bucket.id` and rendered as `bucket divider page → contact sheets → next bucket divider → …`. Buckets are sorted by `Bucket.sortOrder` (matches iOS), photos with `bucketID === null` or pointing at a deleted bucket land in a trailing "Unbucketed" group so nothing gets dropped. Each divider page is a full Letter-size page with a coloured vertical bar matching `Bucket.colorHex` plus the bucket name + photo count — mirrors how iOS presents bucket transitions. New helpers in `htmlReport.ts`: `renderUngroupedContactSheets(...)` (the existing #5.68.1 flow extracted), `renderBucketedContactSheets(...)` (new), `bucketDividerHtml(bucket, count)`, `renderPlanPages(...)` (the existing plan-pages flow extracted). New CSS for `.bucket-divider` styles the divider page. Backwards compatibility: jobs persisted before #5.67.1 had no `sectionOrder` — `applyOptionDefaults` already fills in the iOS default order; legacy `includeFloorPlanPages: false` still suppresses the plan section even when present in `sectionOrder` (legacy switch retired in #5.73.1 when the web modal stops setting it). New imports: `Bucket`, `PdfSection`. Server only — no schema change, no shared change (consumes types from #5.67.1), no iOS change, no web UI change. No `manifestSchemaVersion` bump.
