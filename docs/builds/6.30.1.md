* **Summary:** **Offline manifest retry queue (Wave 4 — the last open sync-robustness item).** A field save whose push failed on a dead spot used to stay unsynced until the next app relaunch (the launch sweep re-pushes everything) or a manual "Sync now" — the failure toast was the end of the story. Now: `ManifestSyncer` keeps a **`pendingRetry` set** of project IDs whose last push failed on a transient error (auth failures still skip silently; the error toast still fires so the user knows the save hasn't synced yet), and **`retryPending()`** re-pushes them when the app returns to the foreground — the natural "network is probably back" moment, wired via `scenePhase` in `SitePhotoApp` (gated on `splashDone` so the initial launch transition doesn't double-fire alongside the launch sweep). Each retry pushes the project's **current** in-memory state, not a stale snapshot, so edits made after the failure ride along, and `pushOnce`'s 3-way-merge path keeps the retry lossless against any server-side changes that landed in between. A project that vanished locally (permanently deleted) drops out of the queue without a push. **Deliberately session-scoped (not persisted), with the reasoning in the code:** cold-start coverage already exists — `pushAllToServer()` re-pushes every project at launch and the disk-vs-base dirty check protects unsynced projects from pulls — so persisting the queue would duplicate an existing guarantee. The missing piece was only the within-session retry, which this adds in ~40 lines. Success paths now also clear the queue (`pendingRetry.remove` next to the existing `dirty.remove`). Backlog row updated. iOS-only; no DB / shared / server / web change.
