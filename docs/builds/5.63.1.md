* **Summary:** Server-side PDF export — PR #2 of 3 for plan item #3. Real report layout on top of the #5.62.1 skeleton. New `server/src/exports/htmlReport.ts` (~360 LOC) assembles a multi-page report: improved cover page (project name, address, GPS coords + accuracy if present, photo + plan counts, generation timestamp), one photo page per non-trashed photo (sequence number + timestamp + plan label header, thumbnail at 5 in, caption + observation, primary + secondary tag chips, AI fields — recommended use, scale present, measurement, reviewer flag), and one floor-plan page per plan (label header, plan image full-width, SVG overlay with numbered blue pin circles at `planPixelX/Y` and color-coded distress markers — point distress as 12 px circles, `crackFloor` as polyline strokes, distress legend below). Plan overlay alignment uses the plan image's intrinsic pixel dimensions for the SVG `viewBox` so pixel-space pin coords land on the right spot at any responsive scale — dimensions read off the raw bytes via new `image-size` dep (no decode needed). Images are pulled from R2 in parallel (concurrency cap 6) and inlined as base64 data URLs so Puppeteer's `setContent({waitUntil: "load"})` resolves without remote subresource fetches; missing objects render a quiet "(image pending sync)" placeholder rather than failing the whole job. Hard cap of 200 active photos per PDF (constant `MAX_PHOTOS_PER_PDF` exported for the future options-sheet PR) — exceeding it throws a clear error that lands in the job row's `error_message` and surfaces in the web UI's tooltip rather than OOMing Chromium on Render's 512 MB tier. The worker's `renderJob` now `await`s `renderReportHtml(project, projectId, log)` instead of the old single-cover-page renderer; `setContent` timeout bumped from 30 s → 60 s to give R2 fetches breathing room. No schema change, no shared API change beyond what #5.62.1 already added, no iOS / web client change. Server only. No `manifestSchemaVersion` bump.
