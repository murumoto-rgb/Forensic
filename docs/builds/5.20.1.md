* **Summary:** Hotfix for the 500 "Database error" the Build #5.19.1 batch endpoint returned on Manandhar (944 photos). The new `POST /photo-urls` handler did `.in("photo_id", [944 UUIDs])`, which supabase-js encodes as a ~35 KB PostgREST query-string filter — past PostgREST/Kong's request-URI length limit, so the query failed. (A second latent bug: PostgREST's default 1000-row response cap would have silently truncated thumb+photo rows for large projects even if the URL fit.) Fix: chunk the photo-ID filter at 100 per query and run the chunks concurrently, then flatten. Each chunk's URL is small and each result set is ≤200 rows. Architecture from #5.19.1 (one client request → grid of URLs) is unchanged; this only fixes the server-side DB query. Server-only PR; no iOS, web, shared, or schema change.
