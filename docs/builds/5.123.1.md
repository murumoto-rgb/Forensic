* **Summary:** **Phase 3, PR 3.3** — the architectural heart of multi-user. New `server/src/access.ts` exports `assertProjectAccess(userId, projectId, minRole)` which resolves the caller's effective role (admin > owner-as-editor > member.role > none) and throws a typed `AccessError` (404 when no relationship to leak-proof existence; 403 when role is below `minRole`). Plus `isOrgAdmin(userId)`, `sendAccessError(reply, err)`, and a new `requireAdmin` preHandler in `middleware/auth.ts` (403s any caller without `profiles.is_admin = true`; ready for the `/v1/admin/*` plugin in PR 3.4). The 8 route files containing the ~16 ad-hoc `.eq("owner_id", request.user.id)` checks all refactor to call the helper: **projects.ts** GET/:id (viewer), PUT update path (editor — both merge and legacy paths; CRITICAL: legacy upsert now preserves `existing.owner_id` so a member-editor can't quietly steal ownership), restore (editor), DELETE (editor); list query (`GET /v1/projects`) becomes a **union of owned + member projects** (admins see all) via `.or("owner_id.eq.<uid>,id.in.(<memberIds>)")`, and each list item gains the caller's `role`. **photos.ts** `resolveObjectKey` + batch `/photo-urls` (viewer). **plans.ts** plan image (viewer). **locks.ts** acquire/heartbeat (editor — viewers can't take the edit lock). **aiTag.ts** re-tag (editor). **files.ts** upload-url + commit (editor); `/sync/files/check` precomputes the caller's owned + member set once and widens the per-row owner filter to "owner OR member OR admin". **projectExports.ts** create (editor), list (viewer; dropped the legacy `created_by = uid` filter — any project viewer sees all exports of that project), GET single (viewer), DELETE (export creator OR project editor/admin). **exports.ts** legacy PDF enqueue (editor). `GetManifestResponse.role` is now populated on every GET. **Out of scope** by deliberate design (commented): `GET /v1/me/storage` quota stays owner-only — broadening would let members inflate each other's quota; the lock force-release stays open (admin-gating is its own separate effort). 67/67 shared tests pass; server + web typecheck clean. No DB migration (the 0014/0015 tables it consumes shipped in PR 3.1). No manifest model touched.
