* **Summary:** Sprint D1 + D2 of the AI-tagging completion plan, bundled — web admin pages for the tag library and AI rules template. Office staff can now edit the team's app-wide AI tagging configuration straight from a browser; iPad is no longer required to administer AI tagging. New `AdminTagLibraryPage` at `/admin/tag-library`: collapsible three-level editor (context → primary → secondary) backed by `/v1/config/tagLibrary` with optimistic-concurrency revision tokens. Inline rename at every level, add / delete buttons, auto-expand contexts on first load, sticky save bar with "Unsaved edits" / "Saved" / revision pill, 409 surfaced as "tag library was modified elsewhere; reload to pick up the latest version." New `AdminAIRulesPage` at `/admin/ai-rules`: monospace textarea over `/v1/config/aiRulesTemplate` with the same save / discard / revision pill / 409 handling. Both pages cross-link to each other in their headers. Project list page header gains "Tag library" + "AI rules" buttons left of "Sign out" so the admin pages are reachable from the top of every signed-in session. UUIDs for new nodes are minted client-side via `crypto.randomUUID()` — same stable-ID discipline iOS uses so a project's `tagSelection` references survive a rename. Reorder + drag-and-drop intentionally deferred (Phase 5 polish; library shape is order-preserving so it can be added without breaking existing selections). The fetch + auth-header machinery for PUT lives inline in each page (rather than going through `api.ts`) because the success body is `{revision: string}` and the 409 path needs a custom error message — duplicating the pattern is smaller than threading two custom return shapes through the central client. iOS picks up the new library / rules at launch / sign-in / "Sync now" via the existing `AppConfigSyncer` from #5.36.1. Web-only PR. No iOS, server, supabase migration, or `manifestSchemaVersion` change.
