* **Summary:** Round 3 PR #1 — server-side persistence layer for the unified Exports surface. RLS read policy scoped to `auth.uid() = created_by`; writes go through the Fastify service role (existing pattern). The existing `pdf_export_jobs` queue stays alongside — PDF rendering still flows through it for backwards compat; PR #2 will adapt the web side to query both tables uniformly. Two new workers: `server/src/exports/folderBundleWorker.ts` streams full-resolution photo bytes from R2 into a `zip` archive via `archiver` + `@aws-sdk/lib-storage` `Upload` (streaming multipart — no temp file on disk) with iOS-matching folder structure (`01 Bucket Name/...`, `99 Unbucketed/...`) and per-folder `captions.txt`; `server/src/exports/csvWorker.ts` emits a one-row-per-primary-tag CSV with RFC-4180 escaping + UTF-8 BOM so Excel renders it. New `server/src/routes/projectExports.ts` exposes `POST/GET /v1/projects/:id/exports`, `GET/DELETE /v1/exports/v2/:exportId` — the `v2` segment avoids colliding with the legacy `/v1/exports/:jobId` PDF endpoint. Deletion reaps the R2 blob via the existing `deleteObjects` helper. Shared types: `ProjectExport`, `ExportKind`, `ExportStatus`, `FolderExportOptions`, `AiAnalysisCsvOptions`, `CreateProjectExportRequest` + matching zod schemas. Parity test scopes the three new wire-only structs into `APP_CONFIG_STRUCTS` (no iOS counterparts — iOS handles export differently via local file writes). New dependencies in `server/package.json`: `archiver`, `@aws-sdk/lib-storage`, plus `@types/archiver` dev. AWS SDK version bumped to `^3.1063.0` for the peer-dep requirement. **No web UI in this PR** — the Exports page lives in PR #2. **No iOS change** — iOS continues to use its local `FolderExportRunner`. **Migration `0011` must be applied to staging before this build's endpoints work.** No `manifestSchemaVersion` bump (this lives outside the project manifest).
