* **Summary:** Seed-on-empty for iOS app-config sync. Until now, iOS only pushed `tagLibrary` / `aiRulesTemplate` to the server when the engineer explicitly EDITED them — a fresh install with bundled defaults never pushed anything, so the server stayed empty and the web admin pages from #5.44.1 rendered blank for teams that hadn't customised yet. `AppConfigSyncer.pullAllFromServer()` now, after attempting to read each known key, falls through to a direct push of the local value when the server's bundle response omits the key. Idempotent across devices: the first device's push wins with `expectedRevision: nil`; concurrent installs get a 409 from `pushTagLibrary` / `pushAIRulesTemplate` which already refetch-and-retry through `refetchAndRetryTagLibrary` / `refetchAndRetryAIRulesTemplate`, landing the same content with the freshly-pulled revision. No per-device data loss because both sides have identical bundled defaults; if a customisation happened post-bundled-default-load on one client, that customisation would already have triggered its own push when the user saved, so the seed-on-empty branch never overwrites real edits. iOS-only PR. No server / web / shared schema change.
