* **Summary:** Tail-end bug fix on top of #5.74.2 — the PDF still rendered "pending sync" placeholders after the files-table lookup landed. Root cause is the same UUID-case bug `routes/photos.ts` fixed back in #5.21.1: iOS manifests store photo IDs in UPPERCASE (`A5F6E276-…`), but Postgres `uuid` columns normalize to lowercase (`a5f6e276-…`) when read back. The DB comparison itself is case-insensitive — the IN clause finds the rows fine. But `resolveFileObjectKeysByPhotoId` was setting `result.set(row.photo_id, ...)` where `row.photo_id` is the DB's lowercase value, so every later `.get(photo.id)` lookup with the manifest's uppercase id missed → null blob → "(pending sync)" placeholder. Fix: build a `requestedByLower: Map<lowercase, originalCase>` of the caller's IDs at the start of the lookup, then resolve every DB row back to the caller's original casing before inserting into the result map. Exact same pattern `routes/photos.ts` uses on line 277 (`requestedByLower`) — copied here for the PDF worker. Server only — no schema change, no shared change, no iOS change, no web UI change. No `manifestSchemaVersion` bump. This closes the immediate Path-C PDF-export gap; next render should produce a real photo PDF for Sarreon 2.
