* **Summary:** iOS-side rename for projects — closes the iOS half of #5.84.1's project-management work. The 11-PR web wave assumed an iOS rename affordance existed; it didn't. This iOS-only PR adds `ProjectStore.renameProject(_:to:)` and a swipe-leading "Rename" action on the active-projects list. The store method validates non-empty / changed names, recomputes `folderName` via `Project.makeFolderName`, attempts an on-disk folder move so the manifest stays co-located with its photos / plans / markups, then calls `save(_:)` (which fires SyncCoordinator's onAfterSave to push the new name to the server). If the folder move fails (locked file, iCloud sync stall) the function rolls back `folderName` to the previous value so the save still lands cleanly in the original folder — a slightly stale on-disk layout but no data loss. UI: `ContentView` gains a leading swipe action ("Rename" / pencil) on active rows and an alert with a TextField for the new name. The existing onDelete gesture was replaced with a trailing destructive swipe action ("Delete" / trash) for consistency with the deleted-projects swipe-actions and to coexist with the new leading action — the alert flow (`pendingDelete`) is unchanged. No schema change. No `manifestSchemaVersion` bump. No web change.
