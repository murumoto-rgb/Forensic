* **Summary:** Backfill visibility fix. The chip on the projects-list footer used to disappear the moment `BinaryBackfillService.backfillAll()` finished, and 404 responses (server has no `files` row for the photo / plan) silently incremented `failedFiles` with no toast, leaving the user with no indication that any sweep had run. Three changes: (1) Footer chip now persists after the sweep completes — green "Backfill: downloaded X of Y files" on success, orange "Backfill: X of Y downloaded; Z couldn't be fetched" when anything missed. Stays on screen until the next sweep starts or the user signs out. (2) Single summary toast emitted at the end of every sweep — clean info-style "downloaded N of M" when there were no failures, warning-style with an explanatory tail when there were ("they may not have been uploaded from any device yet"). (3) Print logs at every meaningful branch — sweep skipped / started / queued-count / per-error 404 / per-error other — so the user (or developer) can confirm the run happened in Xcode's console even when the visible chip raced. No behaviour change to the actual download path; just observability. iOS-only PR. No server / web / shared / supabase change.
