* **Summary:** Web project management — create, rename, soft-delete, restore. The project list page gains a "+ New project" button that opens a modal (name required, address optional); on submit the client generates a UUID, builds an empty `Project` struct that mirrors iOS `Project.init(name:)` defaults (empty arrays for photos/buckets/plans, null GPS, `manifestSchemaVersion: 2`), and PUTs it with `expectedRevision: null` — the existing endpoint already accepts create on that path, so this is a pure client-side capability gain. The list page also gains a collapsible "Trashed projects · N" section below the active list, with a Restore button per row that hits the new `POST /v1/projects/:id/restore` endpoint. Restore exists as a dedicated endpoint because the standard GET returns 404 for `isDeleted: true` (intentional — deep-linking trashed projects shouldn't bypass list filtering), so the server reads the manifest, flips the flag, and writes back atomically without round-tripping the manifest to the client. `InfoTab.tsx` becomes editable for the project name (text input committing on blur, same pattern address already uses) and grows a "Danger zone" section with a "Move to trash" button that confirms, sets `isDeleted: true`, and navigates back to `/projects`. `GET /v1/projects` gains an optional `?trashed=true` query parameter that flips the existing `isDeleted` filter to surface trashed rows for the new section. `api.putProject`'s `expectedRevision` signature loosened from `string` to `string | null` so the create path typechecks (the server already accepted null). Parity matrix updated — the "Create / rename project", "Project GPS + address", and "Soft-delete / restore project" rows all move to ✅ on web. No schema change, no shared API change, no iOS change. No `manifestSchemaVersion` bump.
