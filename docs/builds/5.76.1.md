* **Summary:** Path P #1/8 — tabbed workspace shell + shared manifest hook. Foundation for the iOS-parity work mapped out in `here-are-some-things-dreamy-clock.md`: every per-project workflow (photos, floor plan, AI, buckets, export, info) is moving inside one `ProjectWorkspacePage` that shares a single manifest + single edit lock across tabs, so an edit triggered in one tab is consistent in every other tab without a round-trip. New `web/src/lib/useProjectManifest.ts` extracts the load + optimistic-save loop that was duplicated in `ProjectPlanPage.tsx` (pin drag / distress edit) and `ProjectDetailPage.tsx` (batch re-tag); one canonical implementation handles `pendingRef` coalescing, revision tracking, 409 conflicts, network re-stash, and a unified `SaveStatus` (`loading` / `idle` / `saving` / `saved` / `conflict` / `error`). Hook returns `{project, revision, projectRef, revisionRef, status, save(next), setProject, setRevision, reload}`. `save` updates state AND queues a PUT; `setProject` updates state without queuing — the distinction is what makes the pin-drag confirm dialog work (optimistic UI without uploading the preview). New `web/src/pages/ProjectWorkspacePage.tsx` is the shell: renders a header (project name, address, photo/plan counts, sign-out, save-status pill), the existing `LockBanner`, a tab bar (`Photos` / `Floor Plan` / `AI` / `Buckets` / `Export` / `Info`), and routes to the right tab via nested `Routes`. URL structure: `/projects/:id/<tab>` with `useLocation` driving the active-tab highlight; `/projects/:id` redirects to `/photos`; the backwards-compat `/projects/:id/plan` still works because the Floor Plan tab is at that exact path. Six new tab components under `web/src/components/workspace/`: `PhotosTab` (thin shell around the existing thumbnail grid + lightbox — rich list / filters / editing land in later PRs), `FloorPlanTab` (full port of `ProjectPlanPage`'s canvas + pin drag + distress add/edit + preview panel, rewired to the shared hook), `AITab` (hosts the existing `BatchRetagControl` plus a placeholder for the tag-selection / vocab / clear-AI sections coming in PR #6), `BucketsTab` (read-only bucket listing + counts — CRUD lands in PR #5), `ExportTab` (hosts the existing `ExportPdfControl`), `InfoTab` (project metadata + GPS + counts, read-only — address edit / branding land in PR #8). Old pages retired: `web/src/pages/ProjectDetailPage.tsx` and `web/src/pages/ProjectPlanPage.tsx` deleted (their functionality is now inside the Photos/Floor Plan/AI/Export tabs of the workspace). `App.tsx` route table collapses two project routes into one (`/projects/:id/*`). Behaviour preserved: existing pin drag, distress add/edit/delete, preview panel, batch re-tag, and PDF export all still work — they just live inside tabs now. No schema change, no shared API change, no server change, no iOS change. No `manifestSchemaVersion` bump.
