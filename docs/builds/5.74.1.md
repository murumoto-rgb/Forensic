* **Summary:** Post-Path-C cleanup — two layers of defense against the recurring "Could not find Chrome (ver. 149.0.7827.22)" error on Render. **Root cause diagnosed from the build log:** Chromium WAS being installed correctly at build time (build log shows `chrome@149.0.7827.22 /opt/render/.cache/puppeteer/chrome/linux-149.0.7827.22/chrome-linux64/chrome`), but `/opt/render/.cache/` is Render's **build cache** — it persists across builds but is NOT packed into the runtime container image. So the runtime worker started fresh with no Chromium binary at the path Puppeteer expected. **Layer 1 — correct cache path:** `render.yaml` `PUPPETEER_CACHE_DIR` moves from `/opt/render/.cache/puppeteer` to `/opt/render/project/src/.puppeteer-cache`. Only paths inside `/opt/render/project/src/` are packed into the runtime image. With the cache inside src, the build-time `pnpm --filter @forensic/server exec puppeteer browsers install chrome` now lands somewhere that survives into the runtime container. New `.gitignore` entry for `.puppeteer-cache/` so the binary doesn't accidentally get committed. **Layer 2 — runtime self-install:** new `server/src/exports/ensureChromium.ts` runs on server boot after the HTTP listener binds (so `/healthz` stays up during the install): checks `await puppeteer.executablePath()` for the binary; if missing, uses puppeteer's own `@puppeteer/browsers` sub-dep (now an explicit dep) to download Chromium programmatically into whichever cache dir is configured. Resolves Chromium's `stable` channel — matches what Puppeteer's install script does. Logs the resolved cache dir + elapsed install time. Wired into `index.ts`: `ensureChromium(app.log).then(() => startPdfExportWorker(app.log))` after listener; on failure logs + Sentry-captures + skips worker start (server still serves all non-export routes). With both layers in place, the build phase pre-installs Chromium into a path that survives to runtime (no install delay on cold start), but the runtime install kicks in as a backstop if anything ever drifts. New `@puppeteer/browsers` ^3.0.4 dep on the server. Note: `puppeteer.executablePath()` became async in puppeteer v25 (was sync in earlier majors); the new code awaits. Server + ops only — no schema change, no shared change, no iOS change, no web UI change. No `manifestSchemaVersion` bump.
