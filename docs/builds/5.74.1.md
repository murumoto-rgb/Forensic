* **Summary:** Post-Path-C cleanup — defensive runtime Chromium install. The Path-C PDF export kept tripping on "Could not find Chrome (ver. 149.0.7827.22)" on Render even after the build-command + env-var fixes from #5.66.1. Root cause is brittle: pnpm + Render build cache + `PUPPETEER_CACHE_DIR` env var must all line up across both the build phase and the runtime phase, and any one of those drifting drops Chromium where Puppeteer can't see it. This PR sidesteps the whole chain at runtime. New `server/src/exports/ensureChromium.ts` runs on server boot AFTER the HTTP listener binds (so `/healthz` stays up during the install): checks whether the binary exists at `await puppeteer.executablePath()`; if it does, logs + returns. If not, uses puppeteer's own `@puppeteer/browsers` sub-dep (now an explicit dep so type-checking works) to download Chromium into whichever cache dir Puppeteer is configured to look at. Resolves to Chromium's `stable` channel — matches what Puppeteer's own install script does. Logs the resolved cache dir + elapsed install time so future debugging is straightforward. Wired into `index.ts`: `ensureChromium(app.log).then(() => startPdfExportWorker(app.log))` runs after listener; on failure logs + Sentry-captures + skips worker start (server still serves all non-export routes). New `@puppeteer/browsers` ^3.0.4 dep on the server. Note: `await puppeteer.executablePath()` is now async in puppeteer v25 (was sync in earlier majors). Server only — no schema change, no shared change, no iOS change, no web UI change. No `manifestSchemaVersion` bump.
