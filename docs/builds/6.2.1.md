* **Summary:** **Report branding now syncs between iOS and web (closes the #5.92.1 follow-on).** Web's `/admin/report-branding` editor and iOS's Settings → Report Branding sheet were both live but never talked to each other — each platform kept its own copy and the PDFs could diverge. iOS now treats `app_config.reportBranding` like its other config keys: **pull on launch** (`AppConfigSyncer.pullAllFromServer` overwrites local text overrides via the new `ProjectStore.applyServerReportBranding`, which skips the change hook so a pull never echoes back as a push) and **push on edit** (new `ProjectStore.onReportBrandingChanged` hook fires from `updateBranding(_:)`, debounced 300 ms, 409 → refetch-and-retry — the established tagLibrary pattern). **Field mapping:** the local struct's `coverTitle`/`coverSubtitle`/`footerText` predate the shared schema; the new `ReportBrandingWire` struct carries the canonical `titleOverride`/`subtitleOverride`/`footerOverride`/`logoStoragePath` names, with the mapping (`wireValue` / `applying(_:)`) living next to both shapes in `ReportBranding.swift`. Empty strings normalise to null on push so "cleared on iPhone" reads as "no override" on web. **Logo handling:** `logoStoragePath` (R2 object key, set by web's upload) round-trips opaquely — stored in `branding.json`, never modified by iOS, and on a 409 conflict the server's value is adopted (iOS can't change the logo over the wire, so the server's is by definition newer intent). The local logo PNG (`logoFilename`) stays device-local; actual logo binary up/download is a noted follow-on. **Seed-on-empty** pushes local branding at launch only when `hasContent` — unlike tagLibrary there's no bundled default worth seeding. Old `branding.json` files decode unchanged (new field optional). No server/web/shared code touched (`reportBranding` key + zod schema shipped in #5.92.1); parity matrix row updated.
