* **Summary:** Backfill now populates photo-list thumbnails. After #5.49.1, a device that backfilled full images still showed grey placeholder icons in the photo list / grid because those surfaces render the THUMB file, not the full image — and backfill only fetched full images (the lightbox worked on tap because it loads the full image). Fix: `BinaryBackfillService` runs a local thumb-regeneration pass AFTER the network download sweep. For every photo whose manifest names a thumb that's missing on disk, it regenerates the thumb from the now-present full image via the new `ProjectStore.regenerateThumbnailFromLocalImage(for:in:)` (wraps the existing private `makeThumbnail` at 256px). No network round trip — the server's thumb endpoint only falls back to the full image anyway (iOS uploads just the `photo` kind), so on-device regen from the already-downloaded full image is strictly cheaper. The local pass runs even when there were no network downloads (covers the "full images present, thumbs missing" case from a prior partial backfill). Per-project diagnostic log now reports missing thumb count; summary toast gains a "Rebuilt N thumbnail(s)" tail; the "nothing missing" early-out now also accounts for the thumb pass. Thumbs whose full image is genuinely absent (404'd, never uploaded) stay placeholders — same as the full image being absent. iOS-only PR. No server / web / shared / supabase change.
