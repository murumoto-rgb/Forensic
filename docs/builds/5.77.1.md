The Photos tab now renders one `PhotoListRow` card per photo instead of a thumbnail-only grid: thumbnail (144×108) at left, info column (sequence number `#N`, group glyph for `isPrimary`, AI-pending badge `AI N`, needs-review badge for parse failures / validation / reviewer flag, measurement-visible badge, timestamp `MM/dd/yy @ h:mm a`, location label resolved from `floorPlanID` + placement, bucket badge with color dot, caption preview, tag chips primary-first / secondary-second filtered by the user's confidence threshold) in the middle, and a vertical action stack (favorite, tag-editor stub, relocate stub, overflow stub) at right. New files: `web/src/components/PhotoListRow.tsx` and `web/src/components/PhotoList.tsx`. The list batches one `POST /photo-urls` call up front and feeds the resulting `photoId → url` map down to every row (same pattern `PhotoGrid` already uses; no behavior change to the URL fetching). Favorite toggle is wired through `manifest.save()` so star/unstar persists to the server immediately. Tag / relocate / overflow buttons are rendered as disabled stubs with tooltips pointing at PR #4 where the editor sheet lands. `PhotosTab.tsx` updates to consume `PhotoList` instead of `PhotoGrid`, adds a count header (`Photos · N`), and routes per-photo updates through the shared manifest hook. Confidence threshold reuses the existing `useTagConfidenceThreshold` hook so changes in the AI tab / admin pages propagate to the list without a remount. No schema change, no shared API change, no server change, no iOS change. No `manifestSchemaVersion` bump.
