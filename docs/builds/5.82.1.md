* **Summary:** Path P #7/8 — select mode + batch actions on the Photos tab. The header gains a "Select" toggle (gated on the edit lock) that puts every row into checkbox mode: the row layout shifts to expose a checkbox at the left, the thumbnail click toggles selection instead of opening the lightbox, the right-side per-row action stack (favorite / 🏷 / 📍 / ⋯) hides so the action bar at the top owns the verbs, and selected rows render with a blue border + tinted background. Header shortcuts add "Select all (N)" — selecting every photo in the CURRENTLY-FILTERED set (so filter-then-select-all gives a focused batch) — "Select none", and "Done" (exits select mode and clears the selection). New `web/src/components/SelectionActionBar.tsx` floats above the list when ≥ 1 photo is selected and surfaces four iOS-parallel actions: Move to bucket (select dropdown, with "— None —" to clear), Move to level (select dropdown across `project.floorPlans`, with "— None —" to detach; moving to a new plan nulls the per-photo pixel coords so the photo appears un-placed on the new plan until the engineer drops a pin), Apply tag (text input + Enter / Apply button, appends a confidence-1.0 tag to every selected photo with case-insensitive dedup against existing tags), and Delete (confirmation dialog warns about trash, then soft-deletes via `trashedAt = now` and moves the photos from `photos[]` to `trashedPhotos[]`). Every action is one manifest mutation routed through the shared save loop (`manifest.save(next)`); no new API. Re-tag-with-AI on the selection is deferred — `useBatchRetag` doesn't accept a photoIds filter yet, and bolting one on is a bigger change than warrants this PR; the AI tab's "skip-already-tagged" toggle gives an "untagged-only" axis that covers most of the actual workflow. No schema change, no shared API change, no server change, no iOS change. No `manifestSchemaVersion` bump.
