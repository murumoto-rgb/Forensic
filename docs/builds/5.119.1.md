* **Summary:** Cloud-first **Phase 1, PR 1.4** — the iOS adopt-merge, closing out Phase 1. iOS now sends `baseManifest` on every save and adopts the server's merged response. **Before**: the 409 handler in `ManifestSyncer.swift` was local-wins — it re-fetched the server's revision, *discarded server data*, and re-pushed the local manifest, silently overwriting any concurrent web edit. **After**: the local-wins refetch-and-clobber retry (`refetchRevisionAndRetry`) is gone. `pushOnce` sends `{ project, expectedRevision, baseManifest: storedBase }`; on success it (a) stores the new revision, (b) adopts `response.project` (the merged manifest, written to disk via the no-hook `applyServerProject`) so future edits base on what the server now holds, and (c) advances the stored base. Per-project state in UserDefaults grows by one key: `sitephoto.serverBase.<uuid>` holds the JSON-encoded last-known-server manifest (parallel to `sitephoto.serverRevision.<uuid>`). The Swift `PutManifestRequest` struct gains an optional `baseManifest: Project?` (`encodeIfPresent` so absence flips the server back to the legacy path); `PutManifestResponse` gains an optional `project: Project?`. **First-push migration**: a project that has a revision but no stored base (every existing install on first launch under the new build, for every project) naturally takes the legacy server path — `baseManifest = nil` → server's existing optimistic-concurrency handler runs unchanged, response carries only the revision, and we capture the just-pushed manifest as the base for next time. **No special migration code, no risk of wiping server data**. From the second push onward, the merge path is live. `pullIfNeeded` now does a **dirty-aware** check that survives relaunch: same-session in-memory flag OR the on-disk manifest differs from the stored base (canonicalized through a sorted-keys JSON round-trip to ignore key-order differences). Dirty → push instead of blind-replace (the server merge folds both sides). Clean → adopt server + advance revision + base. `resetRevisions` (sign-out) also clears the new base keys. No DB migration. No manifest-model change → parity contract test unaffected. Server + web typecheck clean; iOS Swift can't be compiled in the sandbox so the parity contract test on PR open carries the final word.
