* **Summary:** Path C #5/8 — implement iOS's `includeMetadataTable` section. Useful for the office reviewer who wants a one-glance index of what's in the report (sort by sequence #, see the date range, scan tags without flipping through contact sheets). New `metadataTableHtml(photos, planLabelById)` in `server/src/exports/htmlReport.ts` produces one `<section class="page metadata-table">` carrying a `<table>` that overflows naturally across pages via Chromium's print machinery: `thead { display: table-header-group }` repeats the column header on every printed page, `tr { page-break-inside: avoid }` keeps a row intact at page boundaries. Columns mirror iOS's `drawMetadataTable` exactly: # (sequence number, monospace, right-aligned), Date (timestamp, ISO short), Plan (label or "—" when un-located), Tags (comma-separated primary tags), Caption (user caption with AI draft fallback), Observation (user observation with AI summary fallback). Section is wired into `renderReportHtml` after `planPagesHtml` when `options.includeMetadataTable === true` (proper `sectionOrder`-driven placement lands in PR #5.71.1). Returns empty string when the selected photo set is empty so an over-filtered export doesn't produce an empty table page. iOS default (`includeMetadataTable: false`) means existing jobs see no behavioral change unless the toggle is set. New CSS for `.metadata-table` styles the header, body, and per-column widths to fit the Letter content area (7.5 in usable width across 6 columns). Server only — no schema change, no shared change (consumes types from #5.67.1), no iOS change, no web UI change. No `manifestSchemaVersion` bump.
