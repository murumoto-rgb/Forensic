* **Summary:** **Fixes Render deploy hanging indefinitely at the corepack step.** The `startCommand` (`pnpm --filter @forensic/server start`) invokes pnpm through corepack, and `package.json` pins `packageManager: pnpm@9.12.0`. On a cold free-tier start where that pnpm version isn't cached in the runtime image, corepack prints `! Corepack is about to download …pnpm-9.12.0.tgz` and then **blocks on an interactive "Do you want to continue? [Y/n]" prompt** that never receives input in Render's non-TTY shell. The server never binds its port, `/healthz` never returns 200, and the deploy spins forever (observed: a 13+ minute hang on the #5.133.1 deploy, which itself contained zero server changes — proving the hang is infra, not code). Fix: add `COREPACK_ENABLE_DOWNLOAD_PROMPT=0` to the server's `envVars` in `render.yaml`, which makes corepack proceed with the download silently instead of waiting on the prompt. The immediate unblock is the same env var added in the Render dashboard (takes effect on the next deploy); this commit makes it durable in the Blueprint so a future service re-create keeps it. No application code touched — `render.yaml` + build doc only. No DB / shared / iOS / web change; parity contract unaffected.
