* **Summary:** Path C #4/8 — implement iOS's four `PdfPlanMode` values for floor-plan pages. Before this PR the renderer hardcoded "photo pins + distress markers on one page" (which happens to be iOS's `merged` mode); now each mode is respected, and `photoOnly` becomes the default to match iOS. New helpers in `htmlReport.ts`: `modeRendersPhotos(mode)` and `modeRendersDistress(mode)` mirror iOS's `PlanRenderMode.{rendersPhotos, rendersDistress}` computed properties exactly (photoOnly = pins on; distressOnly = distress on; photoAndDistressSeparate = both; merged = both). Old monolithic `planPage(plan, planImage, planPhotos)` becomes `planSection(plan, planImage, planPhotos, {includePhotos, includeDistress, subtitle?})` — driven by what overlays the caller wants. The distress legend only renders when distress is actually drawn (no more dead legend on photoOnly pages). New `planPages(plan, planImage, planPhotos, mode)` wraps the per-plan decision: returns ONE planSection for `photoOnly` / `distressOnly` / `merged`, returns TWO for `photoAndDistressSeparate` (first labeled "Photos", second labeled "Distress" via a new italic-subtitle span). The renderer (`renderReportHtml`) now calls `planPages(plan, blob, planPhotos, options.planMode)` per plan instead of the old monolithic call. New CSS `.plan h2 .subtitle` styles the per-page label suffix. iOS-default `photoOnly` is what the user sees when no `planMode` is set — matches iOS's `PDFExportOptions.defaults.planMode = .photoOnly`. Backwards compat: jobs persisted before this PR have no `planMode` in their JSONB; `applyOptionDefaults` already fills in `photoOnly` (the iOS default) for them. Server only — no schema change, no shared change (consumes types from #5.67.1), no iOS change, no web UI change. No `manifestSchemaVersion` bump.
