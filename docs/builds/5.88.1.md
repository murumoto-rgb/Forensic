* **Summary:** Selection-scoped Re-tag with AI on the Photos tab — closes Path P #7/8's deferred follow-on. `useBatchRetag.start()` accepts a new optional `photoIds` parameter (`readonly string[]`); when present, the candidate-build loop restricts to that set (photos outside the set are completely absent from the outcomes map — not "skipped" — to keep the progress UI honest for big projects). `BatchRetagControl` grows three new optional props: `photoIds` (forwarded to `start`), `hideTriggerButton` (parent renders its own trigger), `initiallyOpen` (auto-open the modal on mount), `onClose` (fired when the user cancels the modal without starting OR dismisses the progress panel). `SelectionActionBar` adds an optional "Re-tag with AI" button bound to `onRetagWithAI`; the button is hidden when the parent omits the callback (e.g. the user doesn't hold the edit lock). `PhotosTab` owns `retagSelection` state — clicking the action-bar button snapshots the current `Array.from(selectedIds)` into it, which mounts a transient `BatchRetagControl` with `hideTriggerButton + initiallyOpen`. The `key` prop on the control includes the snapshot's join so repeat triggers force a clean remount. `onClose` flips `retagSelection` back to null. The snapshot approach insulates an in-flight batch from selection edits the user makes after starting. No schema change, no shared API change, no iOS change. No `manifestSchemaVersion` bump.
