* **Summary:** **Web bulk-tag now uses the controlled vocabulary + supports secondaries (closes a P3 reviewer finding).** Web's bulk-tag flow in `SelectionActionBar` was a single free-text input (`SelectionActionBar.tsx:113-136`) and `PhotosTab.applyTag` always wrote `{ label, confidence: 1, parentTag: null }` — no vocabulary constraint, no way to apply a secondary tag from web. iOS's `BulkTagPickerSheet` has shown the controlled-vocabulary tree (primaries + secondaries) and called `store.addTag(..., parentTag:)` since #5.36.1 era. Web users could only get controlled secondaries from the AI-suggestion path, not from manual bulk action. **Fix:** new `web/src/components/BulkTagPickerModal.tsx` — a three-level disclosure (contexts → primaries → secondaries) sourced from `app_config.tagLibrary` (the team-shared library the AI pipeline already uses, synced between iOS and web since #5.36.1; the same data `ProjectTagSelectionPicker.tsx` and `useBatchRetag.ts` consume). One-tap-to-apply UX matching iOS: primaries (teal chips) write `parentTag: null`; secondaries (violet chips, indented) write the primary's name as the parent. Transient 4-second "Applied X" banner at the top confirms each tap. Modal stays open so the user can stack tags; Escape closes (via the existing `useEscapeKey` hook from #6.17.1). **Empty-library fallback:** when `getTagLibraryConfig()` returns `null` (team hasn't seeded yet) or fetch fails, the load-error banner explains why and points the user at Admin → Tag library, but the custom-tag input at the bottom of the modal stays usable — so the bulk-tag flow is never dead. (The free-text input was the only path before; now it's the fallback.) **Wire signature change:** `SelectionActionBar.Props.onApplyTag` is now `(label, parentTag: string | null) => void`; `PhotosTab.applyTag` accepts the new param and the case-insensitive dedup now keys on both `label` and `parentTag` so a primary "Crack" and a secondary "Crack" can coexist (unlikely in practice but allowed by the wire shape). **Documented iOS follow-on:** iOS's bulk picker still reads `ControlledVocabulary.entries` (a hardcoded seed file) instead of the synced `tagLibrary`. iOS and web therefore use *different* vocabularies in this one place until that's aligned. Tracked in `docs/deferred-work.md` as a small follow-on. **Parity check:** no manifest model touched — `Photo.tags` shape, `TagLibrary` shape, both unchanged. No `manifestSchemaVersion` bump; no zod change; no fixture regeneration.
