* **Summary:** Fix pin-drag save failing with browser-side "Method PUT is not allowed by Access-Control-Allow-Methods". `@fastify/cors` v11.2.0 defaults its `methods` allowlist to `'GET,HEAD,POST'` (verified in `node_modules/.../@fastify/cors/index.js:11`) — so the OPTIONS preflight for our manifest PUT advertises only those three methods and the browser correctly blocks the PUT. iOS bypasses CORS via URLSession so iOS saves were unaffected, and previous "save failed" reports were masked by other layers (CORS origin not allowlisted, then 502 storms, then the case-mismatch grid bug). With those fixed, this preflight bug is the next layer. One-line config: explicit `methods: ["GET","HEAD","POST","PUT","PATCH","DELETE","OPTIONS"]` on the cors plugin. DELETE/PATCH listed pre-emptively for Phase 3 PR-C-3 (distress add/edit/delete). Server-only; no iOS, web, shared, or schema change.
