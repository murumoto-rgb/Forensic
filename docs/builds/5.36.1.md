* **Summary:** iOS push + pull for the app-wide config keys whose server-side foundation shipped in #5.35.1. New `AppConfigSyncer` (`@Observable @MainActor`) wires `ProjectStore.onTagLibraryChanged` / `onAIRulesTemplateChanged` hooks — newly added on `ProjectStore` and fired from `persistTagLibrary()` / `persistAIRulesTemplate()` — to a debounced (300 ms, matches `ProjectStore.save(_:)` cadence) `PUT /v1/config/:key` call. Per-key revisions live in `UserDefaults` under `sitephoto.appConfigRevision.*`; 409 on mismatch refetches the bundle and retries once with the freshly-pulled revision. New `AppConfigSyncer.pullAllFromServer()` runs at launch BEFORE `ManifestSyncer.pullAllFromServer` so a project's `tagSelection` lands against the freshest tag library. Settings → "Sync now" picks up an `await appConfigSyncer.pullAllFromServer()` step; sign-out resets revisions alongside the manifest + photo cache resets. New `applyServerTagLibrary` / `applyServerAIRulesTemplate` on `ProjectStore` write the pulled value back without firing the change hook (same pull-doesn't-echo discipline `applyServerProject` uses for manifests). iOS-side wire shapes added in `APIClient.swift`: `AIRulesTemplateWire`, `AppConfigBundleResponse`, `AppConfigPutResponse`, `AppConfigPutTagLibraryRequest`, `AppConfigPutAIRulesTemplateRequest`, plus an `AnyDecodable` + `JSONValue` pair so a bundle entry's unknown jsonb shape can be captured losslessly and re-decoded into the right concrete type. iOS-only PR; no server, web, shared schema, or `manifestSchemaVersion` change. Per the parity contract, the shared TS `TagLibrary` + `AIRulesTemplate` schemas added in #5.35.1 are now exercised end-to-end — but the parity fixture still doesn't include these structs (the `APP_CONFIG_STRUCTS` exclusion from #5.35.1 stays in place). Field-level fixture coverage lands in a follow-up #5.37.x once the regen script learns to read non-manifest Swift structs.
