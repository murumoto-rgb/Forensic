* **Summary:** Fix server `POST /v1/sync/files/check` 500 "Database error" seen in PhotoSyncer pre-check logs (Build #5.51.1+ sessions, projects with hundreds of photo keys). Root cause: Supabase PostgREST URL-encodes the `.in(...)` filter into the request URL. At the client's max chunk of 500 × ~80-char object keys (UUID/UUID/kind triple), the URL overflowed typical 8 KB length limits and Supabase returned a generic 500. Fix: server-side sub-batching at `SUB_BATCH_SIZE = 50` keeps the encoded URL well under 4 KB even at the widest key shape, and merges results across sub-batches before responding. Owner-filter applied per sub-batch unchanged. Logs now include `chunkOffset` + `chunkSize` so a future failure is debuggable per-batch rather than per-request. Server-only PR. No iOS / web / shared / supabase migration / `manifestSchemaVersion` change. After deploy, PhotoSyncer's repeated `[PhotoSyncer] sync-files-check chunk failed at offset 0: http(status: 500, ...)` should stop appearing in the iOS console.
