* **Summary:** Cloud-first **Phase 1, PR 1.3** — web now sends `baseManifest` on every save and adopts the server's merged response. **Before**: a save raced against another writer (web tab or future iOS) lost on 409 with "modified elsewhere — reload" and the user had to redo their edits. **After**: `useProjectManifest` holds a `baseRef` (the manifest the server last confirmed we held, set on load and after each successful save). The save loop sends `baseManifest = baseRef` to `PUT /v1/projects/:id`; the server runs `mergeManifest(baseManifest, current, project)` (from #5.117.1) and returns the merged manifest in `resp.project`. The hook adopts: `baseRef` always advances to merged; UI state (`project` / `projectRef`) advances **only when no fresher edit is queued in `pendingRef`** — otherwise the merged value would briefly flash over the user's just-typed text before the loop re-applies it. The user keeps typing → next iteration sends `base = merged + their new edits` → idempotent merge converges. `api.putProject` gains an optional `baseManifest?: Project` parameter (the body shape is unchanged when omitted). Legacy responses (server skipped merge) advance `baseRef` to the just-pushed manifest, preserving correctness during the rollout window. The `conflict` status stays as a defensive fallback for a true 409 (`merge_cas_exhausted` after server-side retries, or a legacy-path miss). No DB migration; no manifest-model change → parity untouched.
