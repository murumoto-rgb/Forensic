* **Summary:** Final piece of the Collaboration-safety milestone (#6 + #10 bundled with #5.59.1 + #5.60.1): Resend transactional emails fire when the lock changes hands without the holder's consent. New module `server/src/email/resend.ts` initializes the Resend SDK conditionally on `RESEND_API_KEY` + `RESEND_FROM_EMAIL` + `WEB_BASE_URL` (all three required so the "Open project" link in the mail body has a host); every helper no-ops cleanly when any var is blank, mirroring the `sentry.ts` pattern. New `server/src/email/templates.ts` defines two transactional templates that return `{subject, html, text}` ready for `sendEmail()`: `lockForceReleasedEmail` ("Your edit lock on X was taken — Y force-released it") and `lockExpiredTakenOverEmail` ("Your lock expired and Y has taken over"). Both use inline-styled HTML matching the in-app neutral palette + a plain-text fallback so corporate mail filters that strip HTML still render usefully; no remote images. Wired into `server/src/routes/locks.ts`: (a) the force-release path reads the prior holder's email BEFORE the delete, then fires `lockForceReleasedEmail` to them after the delete succeeds; (b) the acquire path fires `lockExpiredTakenOverEmail` when the existing row was expired AND owned by a different user. Both sends are fire-and-forget (`void (async () => …)()`) so the API response doesn't wait on the hosted SMTP relay; failures land in Sentry as warning-level `captureMessage` calls but never bubble to the route. Project name for the subject lines comes from a new `loadProjectNameOrFallback(projectId)` helper that gracefully falls back to the project UUID. Three new env vars wired through `env.ts`: `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `WEB_BASE_URL` — all optional, all documented in `.env.local.example` and `docs/deploy.md` under the Render section. New `resend` npm dep in `server/package.json` (^6.12.4). Server only — no client / iOS / shared change. No `manifestSchemaVersion` bump.
