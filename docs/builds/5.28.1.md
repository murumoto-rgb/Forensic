* **Summary:** Three plan-page preview-experience improvements, mirroring iOS `PlanViewerView`.
  **(1) Auto-recenter the canvas on the previewed photo.** When the preview panel is open, the canvas pans (without changing zoom) so the previewed pin lands at the centroid of the visible portion — the canvas area NOT covered by the docked preview. Discovered at recenter time via `document.querySelector("[data-preview-panel]")` so the canvas doesn't need to know the panel's pixel dimensions ahead of time. Re-fires on every preview navigation (prev/next, arrow key, thumb click). Mirrors iOS `pendingRecenterID` + `withAnimation(.easeInOut(duration: 0.25), value: selectedPhotoID)`.
  **(2) Thumbnail strip in the preview panel.** Horizontally-scrolling row of small thumbnails (56×56) just below the header, one per photo in the active nav scope (Group or All on plan). Thumbs come from one batch call to `POST /v1/projects/:id/photo-urls` per scope change. Current photo's thumb is bordered + auto-scrolled into view via `scrollIntoView({ inline: "center" })`. Click a thumb → navigate to that photo (canvas re-centers in the same step).
  **(3) More aggressive preload.** Bumped `PRELOAD_RADIUS` from 2 to 5 for the panel's full-image preload (so paging up to 5 photos in either direction is instant for a typical click cadence). Thumbs are pre-fetched as a batch on scope change, so the strip renders fully populated instantly.
  Side change: `PhotoPreviewPanel` is now a **controlled** component — `selectedPhotoId` lives in `ProjectPlanPage` so the canvas can observe it for recenter. Web-only; no iOS, server, shared, or schema change.
