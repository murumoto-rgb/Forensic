* **Summary:** **Web photo-grid lazy rendering (Wave 4 — closes the "virtualization" backlog item with a deliberately safer mechanism).** Each photo card in `PhotoList` is now wrapped with `content-visibility: auto` + `contain-intrinsic-size: auto 360px`: the browser **skips layout and paint entirely for off-screen cards** — on a 300-photo project that's ~95% of the grid at any scroll position — while the intrinsic-size hint keeps the scrollbar stable before a card's first render (the `auto` keyword makes the browser remember each card's real measured size afterwards). The thumbnails already carried `loading="lazy"`, so network fetches were lazy; this completes the picture by making the *rendering* lazy too. **Why not react-window-style virtualization (the original backlog phrasing):** windowing requires rewiring the scroll container, breaks the page-level scroll the workspace relies on, interacts with selection mode and the filter-driven array changes — and a regression there ships straight to production (Vercel deploys on merge) where it can't be caught without a browser. `content-visibility` captures the same render-cost win (layout/paint skipping is where the jank lives — the DOM nodes themselves are cheap once not rendered) with **zero structural change**: identical markup semantics, selection/filters untouched, graceful degradation to today's exact behavior on the rare browser without support. Full windowing remains an option if 1,000+-photo projects materialize; the backlog row records that. Also deduplicated a doubled eslint-disable comment left by #6.17.1.
