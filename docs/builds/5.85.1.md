* **Summary:** New `/settings` route gives the web app a counterpart to iOS Settings. Four sections, each in its own card: **Account** (email, password change via `supabase.auth.updateUser`, sign-out — device-local, same as the existing button so a web sign-out doesn't kick the iPhone session); **AI tagging** with three controls (Claude Sonnet 4.6 / Haiku 4.5 picker, confidence-threshold slider 0–1 step 0.05, parallel-request slider 1–20 step 1); **Team-wide config** with the two existing admin editor links (tag library, AI rules template) plus a note that report branding is still a follow-on; **Diagnostics** showing build number, branch, SHA, and timestamp — consolidates what `BuildInfoFooter` already shows so it's reachable inside the app rather than only the corner badge. New `useUserPrefs` hook owns the localStorage backing for all three AI prefs — same storage-event + custom-event signaling pattern `useTagConfidenceThreshold` uses, with the threshold key (`sitephoto.tagConfidenceThreshold`) shared so the two hooks stay in lockstep. New storage keys: `sitephoto.aiModel`, `sitephoto.aiConcurrency`. `BatchRetagControl` now reads its initial model + concurrency defaults from `useUserPrefs` instead of hard-coding `{ model: "claude-sonnet-4-6", concurrency: 3 }` — opening the modal each time refreshes the defaults from current prefs (the per-batch override still doesn't write back). Gear-icon links added to the project list header AND the workspace shell header so settings are one click away from anywhere. Multi-device sync of prefs (server-backed) is a separate later PR; today every browser maintains its own copy. No schema change, no shared API change, no iOS change. No `manifestSchemaVersion` bump.
