* **Summary:** Bug fix + small extension to the folder-bundle export shipped in #5.97.1. **Bug**: the original worker constructed R2 keys as `${projectId}/${photoId}/photo` from manifest IDs. iOS sometimes uppercases UUIDs in the R2 path while the manifest carries them lowercase, and R2 keys are case-sensitive — so every `getObjectBytes` call 404'd silently and the worker logged-and-continued, leaving only `captions.txt` in each bucket folder. **Fix**: query the `files` table for the actual `object_key` for each photo (same idiom the existing photos route uses), and use that real key for the R2 fetch. Lookup happens per-bucket with one `WHERE project_id = ... AND photo_id IN (...) AND kind = 'photo'` query. **Extension**: new `00 Floor Plans/` folder at the top of the ZIP. Includes each plan's binary (looked up the same way — `kind = 'plan'` files row) with a numeric `01_`, `02_` prefix; a `plans.txt` sidecar lists per-plan calibration values (pixelsPerFoot, calibrationDistanceFeet, anchor coords in pixels + local feet, northDeg) + distress marker count. iOS's `FolderExportRunner` doesn't include plans today; the user asked for them on web, so web is the leader here. No schema change. No `manifestSchemaVersion` bump.
