* **Summary:** **Performance PR 1 of the iOS review (Wave 2): kills the main scroll-stutter source + two classes of redundant allocation.** (1) **Async cached thumbnails.** Photo rows and plan rows rendered their thumbnails via synchronous `Data(contentsOf:)` + `UIImage(data:)` — a disk read + JPEG decode **on the MainActor for every visible row, on every render**. New `CachedThumbnail` view (Views/CachedThumbnail.swift) loads + decodes off-main in a `.task(id:)`, forces decode via `preparingForDisplay()`, and stores into a process-wide `NSCache` (count-limited, memory-pressure-evicting) keyed by path + file mtime so replaced files self-invalidate. Plan rows were the worst case — they have no dedicated thumb file, so the old code decoded the **full-resolution plan image** for a 56×42 row; they now downsample via ImageIO (`CGImageSourceCreateThumbnailAtIndex`, max 240 px) so the cache holds a small bitmap, never the whole drawing. First render shows the same placeholder glyphs as before; steady-state scrolling hits the cache and never touches disk. (2) **Shared JSON coders.** `ProjectStore.decoder()`/`encoder()` built a fresh `JSONDecoder`/`JSONEncoder` on every call (hundreds across a load/save burst; 4+ per photo during batch-tag checkpoints). Now backed by `static let` instances — config is set once and never mutated, and all use is MainActor-serialized; the accessor functions remain so ~80 call sites needed zero churn. (3) **PDF render-loop hoists.** `PDFExportService` re-read `sitephoto.tagConfidenceThreshold` from UserDefaults and rebuilt a `DateFormatter` on **every contact-sheet page**, and re-read `sitephoto.bubbleScale` on every `drawBubbles` call. All three are now per-export snapshots / static formatters (the service struct is constructed fresh per export, so nothing can go stale mid-run — and both the `countPages` pre-pass and the render phase now read the same snapshot, which is strictly more consistent than two reads). The metadata-table's per-page formatter got the same treatment. **No behavior change anywhere** — same images, same layout, same PDF output; pagination logic untouched (two-phase countPages/render discipline preserved — the hoisted values feed both phases identically). New file `CachedThumbnail.swift` is picked up by xcodegen's directory scan; run `scripts/sync-ios.sh` as usual. No DB / shared / server / web change; parity contract unaffected.
