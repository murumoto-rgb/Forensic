* **Summary:** Phase 4 iOS half — wires the `POST /v1/ai/tag-photo` proxy shipped in #5.32.1 into the iOS AI-tagging path. New Settings toggle "Use team server for AI" (Settings → AI Tagging Speed) writes to `sitephoto.aiTagging.useBackend`; when on, every AI tagging call — both the per-photo "Suggest with AI" button (`PhotoTagEditorSheet.runClaude`) and the batch "Auto-tag all photos" task group (`ProjectStore.batchAITag`) — routes through the Forensic backend instead of api.anthropic.com. Backend path uploads no image bytes from the device (server fetches them from R2 by `photoId`) and doesn't read the device Keychain. New `APIClient.tagPhoto(projectId:photoId:model:systemPrompt:userText:maxTokens:)` method posts to the endpoint; new `AITagPhotoRequest` / `AITagPhotoResponse` wire shapes mirror `packages/shared/src/api.ts`. New `ClaudeTaggingService.tagViaBackend(...)` is a sibling of the existing `tag(...)` device-key method — it flattens the cache-aware multi-block system prompt into a single string (backend endpoint is single-turn today) and reuses the same JSON-extract-and-validate parser through a new extracted `parseResult(fromText:fallbackPhotoID:vocabulary:)` overload, so output shapes can't drift between paths. `ProjectStore.apiClient` slot added and wired in `SitePhotoApp.init`. Repair-retry on vocabulary rejections runs only on the device-key path (backend endpoint doesn't yet accept multi-turn messages); follow-up can extend the endpoint if backend-side repair proves worth the complexity. Toggle off by default — existing users keep the device-key behaviour they had before. No shared-schema, server, or web change; no `manifestSchemaVersion` bump.
