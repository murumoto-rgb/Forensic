* **Summary:** Web file upload for photos and floor plans — closes the long-standing follow-on. Reuses the existing `POST /v1/projects/:id/files/upload-url` + `/files/commit` endpoints iOS has used since #5.9.1, so no server work this PR. New `web/src/lib/uploadFile.ts` is the three-step helper (request presigned URL → PUT to R2 → commit registry row); the R2 PUT goes through plain `fetch` so the Authorization header isn't injected (R2 rejects unrecognised auth headers). New `AddPhotosControl.tsx` renders a "+ Add photos" button on the Photos tab — file picker multi-select `image/*`, 3-concurrent upload pattern (same shape `useBatchRetag` uses), per-file progress panel docked bottom-right with ✓ / ✗ status icons. Each uploaded photo is appended to `Project.photos` with a sequential `sequenceNumber`, an `imageFilename` of `<uuid>.<ext>` (matching iOS convention), and the same iOS-mirroring defaults `Photo.init` uses. No client-side thumbnail generation — the server's thumb endpoint already falls back to `kind=photo` when no thumb row exists (Build #5.55.1's fallback path), so the rich list keeps working on web-uploaded photos. `FloorPlanManager` grows a "+ Add plan" affordance — single-file picker, placeholder calibration values (50 px/ft, zero anchor, north 0) since the pinch + tap calibration UI is iOS-only; the user tunes on iOS afterward. Empty-state Floor Plan tab now renders just the FloorPlanManager so users can upload their first plan from web. The "+ Add plan" affordance also auto-activates the first uploaded plan when `activeFloorPlanID` was null. No schema change, no shared API change (everything was already there for iOS), no iOS change. No `manifestSchemaVersion` bump.
